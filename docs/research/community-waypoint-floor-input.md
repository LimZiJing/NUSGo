# Community Waypoint floor input research

Date: 2026-11-11

## Question

How should the Community Waypoint floor picker use building-specific data, keep uncommon floors available, and show an unset optional floor?

## Findings

- NUSGo defines `floor` as an optional signed integer relative to ground: negative is below ground, zero is ground, and positive is above ground. The submission picker uses B1, G, 1–5, and Other by default; a matched building can show its observed room floors. Other accepts a signed integer. [Domain glossary](../../CONTEXT.md), [Community Waypoint data contract](../community-waypoints/data-contract.md), [submission form](../../frontend/src/features/waypoints/community/submission/form.tsx), [shared floor label](../../shared/src/waypoints/community.ts).
- OpenStreetMap's indoor `level` convention uses a numeric vertical order: ground is `0`, the floor above it is `1`, and the first basement is `-1`. It explicitly allows `level:ref` for the local floor designation shown on signs; its example pairs `level=-1` with `level:ref=B1`. The documentation also notes that everyday floor numbering differs across places and buildings. [OSM `level`](https://wiki.openstreetmap.org/wiki/Key:level), [OSM `level:ref`](https://wiki.openstreetmap.org/wiki/Key:level:ref).
- NUS materials use human-facing labels such as **Basement 1**, **Level 1**, and **B1**. UCI's facilities list both Basement 1 and Level 1 locations, while the AS8 venue guide describes a directory sign marked “1st Storey” with a “B1” car-park level. This supports presenting familiar labels in the form instead of exposing `-1`, while also showing why exact signage can vary. [NUS UCI Facilities and Amenities](https://uci.nus.edu.sg/campus-life/housing-services/general-information-for-student-housing/facilities-amenities/), [NUS AS8 venue guide](https://fass.nus.edu.sg/ecs/wp-content/uploads/sites/4/2022/03/Roadmap-for-Conference-Venue.pdf).
- Esri's floor-aware model also separates order from the name people see. It defines `LevelNumber` separately from `VerticalOrder`; the number shown by a facility can differ from actual vertical order, while `LongName` and `ShortName` provide display names. Esri describes the short name as suitable for a compact control such as a drop-down, and its Indoors model uses zero for ground with negative and positive vertical orders below and above ground. [ArcGIS Maps SDK floor levels](https://developers.arcgis.com/net/maps-2d/use-floor-aware-maps/), [ArcGIS Indoors floor-plan mapping](https://pro.arcgis.com/en/pro-app/3.0/help/data/indoors/map-floor-plans-to-indoors.htm), [ArcGIS Indoors information model](https://pro.arcgis.com/en/pro-app/3.1/help/data/indoors/arcgis-indoors-information-model.htm).

## Building-specific floor data

- The checked-in building catalogue has no floor count or floor-list fields: the [`Building` type](../../shared/src/venue/buildings.ts) contains identity, location, room-code prefixes, and optional address fields. The separate [`venues.json`](../../frontend/public/data/venues.json) has floor values for individual rooms. In the current files, 719 of 729 venue records have an integer floor, with observed values from `-1` through `10`. Joining those room venues to the current building search entries yields at least one observed floor for 74 entries. These are room-level observations, not each building's complete floor range. [Building catalogue](../../frontend/public/data/buildings.json), [venue catalogue](../../frontend/public/data/venues.json), [building-room linking](../../frontend/src/domain/venue/building-links.ts).
- NUSMods documents that its venue list represents locations used for classes in a semester and is not a comprehensive location list. That makes its floor values useful for suggestions but incomplete for building inventory. [NUSMods API venue-data notes](https://api.nusmods.com/v2/).
- NUS's official room-code guide says `AS4-03-05` uses `03` to indicate the third floor. It documents how to interpret a known room code, but does not enumerate each building's complete floor range. [NUS AY25/26 First-Year Guide](https://www.nus.edu.sg/nusone/wp-content/uploads/NUSOne-First-Year-Guide-Final.pdf).
- NUS's public campus-map help describes search by building or street name, not a building floor inventory. NUS UCI's housing facilities page gives floor references for selected facilities and blocks, including basements and level ranges, but is not a campus-wide inventory. [NUS Campus Map help](https://map.nus.edu.sg/index.php/help), [NUS UCI Facilities and Amenities](https://uci.nus.edu.sg/campus-life/housing-services/general-information-for-student-housing/facilities-amenities/).
- NUS CDE lists campus maps and plans and says access requests for confidential campus data go through department coordinators. A complete verified list may require plan access or building-by-building verification. [CDE Maps, Plans & Drawings](https://cde.nus.edu.sg/information-resource-centre/maps-plans-drawings/).

The research found no complete public, structured NUS source of floor counts by building. The existing room data can still provide building-specific **observed floor choices**, as long as **Other** remains available because the venue list is incomplete. A typed or unmatched building name has no reliable building key; use the generic defaults in that case.

## Recommendation

Keep the optional stored `floor` as an integer. Start with **Not set**, then show **B1, G, 1, 2, 3, 4, 5, Other…** when no building is selected. Map B1 to `-1`, G to `0`, and positive labels to their matching positive integers. For an exact selected building with room-floor data, show its distinct observed values instead, plus **Other…**; if it has no floor observations, keep the generic defaults. Other accepts any signed safe integer with no UI `min` or `max` (`-3` for B3, `12` for twelve levels above ground).

This is a user-directed picker shape supported by the available data: building-specific room floors make the common list more relevant, while **Other** covers real floors missing from the incomplete venue catalogue. If a typed building does not match a catalogue selection, retain the generic defaults. Leave the field at **Not set** when the contributor is unsure.

Use **Not set** as the empty-value option instead of a run of dashes. It means the optional floor was left unspecified; **None** could suggest that the building has no floors. A muted text color may reinforce the unset state on the closed control, but the words should carry the meaning. WCAG says color cannot be the only visual cue, and the HTML Standard describes how a required select's empty placeholder should appear; this optional field should keep **Not set** as a selectable value so a contributor can clear a floor. [WCAG 2.2 SC 1.4.1](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color), [WHATWG HTML Standard: select rendering](https://html.spec.whatwg.org/multipage/rendering.html#the-select-element).

Keep arbitrary strings such as `B1`, `G`, `L1`, or `Mezzanine` out of the stored `floor` value. They can be local display references rather than consistent vertical positions. If verified building signage must later appear verbatim, add a separate maintainer-authored display reference (similar to OSM `level:ref` or Esri's `ShortName`) instead of overloading `floor` or asking contributors to guess the mapping.
