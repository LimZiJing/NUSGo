# Astryx UI inventory

Snapshot of the frontend on `main` after PR [#683](https://github.com/LimZiJing/NUSGo/pull/683) merged. This records current controls and compatibility decisions; it does not change UI behavior or authorize a bulk migration. `docs/ui/controls.md` remains the source of truth for NUSGo control sizes, states, themes, and accessibility requirements.

## CLI setup

- `@astryxdesign/cli` is a frontend development dependency pinned to `0.7.16`, matching the Core dependency added to the app by merged PR #683.
- Use the project CLI with `npx astryx <command>`; no global install is needed. Useful reads are `npx astryx doctor --json`, `npx astryx component Button --props`, and `npx astryx search <term>`.
- `astryx init --features agents --agent codex` added the managed guidance block to the repository's `AGENTS.md`. The surrounding scope note keeps its greenfield advice from overriding NUSGo's existing UI standards.
- From the repository root, `npx astryx doctor --json` reports no failed checks; Core and CLI are aligned at `0.7.16`, and it recognizes the Astryx section in `AGENTS.md`.
- Doctor warns that no Astryx theme package is installed. This is expected because NUSGo manages its own six themes. Its PATH check also warns about the local `node_modules/.bin/astryx.cmd`; running that shim directly and invoking it through `npx astryx` both report CLI `0.7.16`, so use the documented `npx` command for project work.

## Current controls and decisions

| Control or pattern | Current use and contract | Astryx equivalent | Decision |
| --- | --- | --- | --- |
| Map overlay actions: More, Location, Live buses | `MoreEntryButton`, `LocationControl`, and `LiveBusToggle` sit over the map. More exposes `aria-expanded`/`aria-controls`; Live buses exposes a pressed state and toggles visibility; Location has a changing accessible label, a custom spinner, `aria-busy`, and a live status message. Keep the 44px target. Overlay colors use NUSGo theme tokens; on mobile the actions move into a safe-area-aware pinned column, including short landscape screens. | `Button` and `IconButton`; NUSGo adapters preserve map-specific props and styles. | **Pilot merged.** PR #683 migrates these three through a NUSGo adapter and preserves their state ownership and labels. It deliberately keeps the Location spinner and announcement: Astryx `isLoading` blocks repeat activation and announces generic loading, which changes the current interaction. Use the pilot as the reference slice before expanding. |
| Shared Button / IconButton family | Used across Explore, Plan, Stops, More, Waypoints, Settings, and Live buses. NUSGo wrappers define primary/secondary/ghost variants, 36px/44px sizes, focus, disabled, pressed, and theme-token states across all six themes. Feature layouts size or expand rich rows at their breakpoints. | `Button` and `IconButton` have matching action roles, sizes, variants, and async loading, but loading and pressed behavior need an adapter. | **Migrate by slice.** Keep NUSGo wrappers as the app-facing API; do not replace imports across the repository in one pass. |
| `BackButton` | Used in Explore, Stops, Plan, More, and Waypoints for returning to a previous panel or category. `header` has a labelled icon-only button; `inline` and `label-only` expose a text label. It inherits Button/IconButton token colors in all six themes. Header sizing follows the shared control; inline mode keeps a documented 23px target exception and has no separate breakpoint behavior. | `Button` and `IconButton`; no direct Astryx `BackButton` component. | **Keep the NUSGo wrapper.** It preserves three app-specific modes and the compact inline geometry while allowing a later primitive change beneath it. |
| `NavigateButton` | Used on Explore venue details and Stop details as the primary navigation action. It names the action “Navigate”, accepts a contextual accessible label override, and exposes native disabled state. It uses the primary theme tokens; the feature layout controls its width at each viewport. | Astryx `Button` with an icon. | **Keep the NUSGo wrapper.** It centralizes the navigation icon, accessible label, disabled state, and app-specific sizing. |
| `MenuItem` | Used for actions in Plan trip actions and Personal Waypoint list popovers. It is a native button with a text accessible name, native disabled behavior, and a full-width ghost row; hover, focus, and surface colors use NUSGo tokens. The row fills its menu at any viewport and has no separate breakpoint style. | `DropdownMenuItem` is the closest equivalent; it exposes `role="menuitem"` and menu-specific close behavior. | **Defer.** First confirm the containing popovers use menu semantics and that changing the current button role and close behavior is correct. |
| Mobile navigation tabs | The `MainNavigation` landmark has three buttons for Explore, Stops, and Plan. Each exposes `aria-current="page"` when active and `aria-controls` for its panel. Tab colors, focus, and active state use NUSGo tokens. This bar appears only at the mobile breakpoint, uses three equal columns in a 56px pill, and honors bottom safe-area insets. | Astryx `TabList` and `Tab` can render a navigation landmark with `aria-current`; explicit `tablist` mode changes the keyboard and selection semantics. In navigation mode, `panelId` does not wire `aria-controls`. | **Defer.** Compare the custom mobile pill layout and preserve both current-page and panel-control semantics before replacing it. |
| Select | NUSGo `Select` is used in Appearance settings and venue details. It is a portal listbox that follows its trigger, supports Arrow/Home/End/Escape, closes on outside click, and restores focus after selection. Its surfaces and focus states use NUSGo tokens across all six themes; the popup repositions on scroll/resize and is capped to the available viewport height. | `Selector` is the closest named component in Core. | **Defer.** Compare keyboard behavior, portal positioning, selected styling, and all six NUSGo themes before replacing the custom primitive. |
| SegmentedControl | Used in Explore and Stops as a labelled group of toggle buttons. Each option is a button with `aria-pressed`; selected values are controlled by the feature. Shared theme tokens supply selected, focus, and disabled states; each feature owns the group's width and narrow-screen layout. | Astryx `SegmentedControl` is a controlled segmented radio group. | **Defer.** Its radio-group semantics differ from NUSGo's button-group contract. Only migrate if the accessibility semantics and feature behavior are intentionally changed and reviewed. |
| Chip, RouteChip, Pill, InfoPill | NUSGo `Chip` is an interactive `aria-pressed` choice; `RouteChip` carries official route colours; pills are non-interactive labels. Shared tokens handle ordinary chip and pill colors in all six themes; route colors and compact sizes are documented exceptions. Features own wrapping and overflow in narrow layouts. | Core has `Token` and `Badge`, but no direct `Chip` component. `Badge` is not a substitute for an interactive choice. | **Keep NUSGo wrappers.** There is no direct equivalent for the current selection and route-color contracts. |
| Reachable-stops popover | Base UI `Popover` is used by the reachable favourite-stops feature. Its keyboard-operable button has a count label; the non-modal popup is a named dialog containing a destination list. Escape and outside press dismiss it, with focus returned to its trigger. The 4px offset and 8px collision padding let it reposition; the popup is capped at `min(280px, viewport width - 16px)`. Its themed styles are mounted in the panel scroll container, so it moves and clips with the stop cards instead of floating over the sheet. | Astryx `Popover` supports controlled open state, placement, focus options, and adaptive popover/bottom-sheet presentation. | **Candidate after the button pilot.** This is a contained feature slice; compare trigger anchoring, focus, dismissal, viewport sizing, and map/sheet interaction first. |
| Waypoint forms | Base UI `Autocomplete`, `Field`, `Form`, `Input`, `Radio`, and `RadioGroup` support Personal and Community Waypoint forms, including labels, validation, selection, and submission. Form surfaces and validation states use NUSGo theme tokens. Long forms scroll inside their panels; personal/community layouts reflow at phone widths, and floor choices can scroll horizontally. | Core has `Field`, `TextInput`, `Typeahead`, `RadioList`, and `FormLayout`; there is no direct `Form` equivalent identified. | **Defer by feature.** Preserve validation, autocomplete keyboard behavior, selected values, and submit/error announcements. Migrate only after a full form-flow comparison. |
| Mobile sheet | Base UI `Drawer` powers the Explore/Stops/Plan sheet. NUSGo adds dynamic snap points, non-modal behavior, persistent mounted tabs, custom drag handling, active/inactive accessibility state, and map coordination. Its surfaces follow NUSGo theme tokens; it is mobile-only and tracks viewport height and safe areas. | Astryx `BottomSheet` supports configurable `snapPoints` and a non-modal mode, but its documented API does not expose a controlled active detent/change callback. | **Defer; highest risk.** Saved detents, persistent tabs, dismissal, and map coordination still need a parity proof. Do not remove Base UI based on the button pilot. |
| Search and scrolling | NUSGo `SearchField` and `ScrollArea` are reused by venue and waypoint flows. Their clear actions, query state, and feature-specific scroll containment belong to NUSGo. They use theme tokens in all six themes; fields fill their feature panel and scroll areas follow its responsive height. | Core has `TextInput`, `Typeahead`, and `ScrollableArea`. | **Defer.** Consider only with a concrete screen slice and parity checks for clear/query behavior, keyboard use, and scroll containment. |

## Baseline and order

PR #683 reports matched pre-rebase builds of 599.19 kB JS gzip + 38.27 kB CSS gzip before the pilot and 659.23 kB JS gzip + 80.84 kB CSS gzip with the pilot: **+102.61 kB gzip total** for the three-button slice. Its post-rebase total is not a direct pilot delta. Treat this as a reference measurement, not a forecast for other controls.

1. Use the merged three-button pilot as the accepted first slice; compare each follow-up's accessibility, behavior, and bundle delta against its own baseline.
2. Evaluate the reachable-stops popover as the next small, isolated candidate.
3. Consider Select and SegmentedControl only after their keyboard and ARIA contracts are compared with the NUSGo versions.
4. Treat waypoint forms as a feature-flow migration; keep the mobile sheet on Base UI unless snap-point and persistence parity is demonstrated.
5. Keep route chips, interactive chips, pills, and NUSGo theme ownership on their current wrappers until Astryx offers a direct compatible contract.
