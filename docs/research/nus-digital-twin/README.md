# NUS Digital Twin buildings import

`frontend/public/data/buildings.json` is generated from a one-off snapshot of the NUS Digital Twin buildings API (`GET https://www.nus-digital-twin.com/api/v1/buildings`, v1 beta, no key needed). See #260 for the decisions behind it.

## Credit

Buildings: NUS Digital Twin (City Syntax Lab). The API documentation says the data is sourced from OpenStreetMap and Google Maps by City Syntax Lab researchers. The credit is recorded in the `source` field of `buildings.json` (`name`, `url`, `fetchedOn`, `licenceNote`). The in-app credit belongs in an About or settings footer once the settings menu exists (#334).

## What is in this folder

- `buildings-raw-YYYY-MM-DD.json`: the raw API response, committed so the import is reproducible. The date is the Singapore calendar day of the fetch.
- `dedupe-report.md`: generated by the import. It lists unlinked buildings, room prefixes without a building, ambiguous matches, repeated names, distance warnings and standalone-venue candidates. Do not edit it by hand.

## Re-running the import

Offline, from the latest committed snapshot (no network, safe to repeat; the same inputs give byte-identical output):

```bash
npm run buildings:import
```

To take a new snapshot (one request, no credentials; refuses to overwrite an existing snapshot unless `--force` is given):

```bash
npm run buildings:import -- --fetch
```

The import exits without writing anything if the response is invalid or empty, or if the record count is more than 10% below the previous snapshot. That needs a manual review.

## Corrections

- `scripts/data/building-overrides.json` is hand-edited and committed. Entries are keyed by API `elementId` and win over the API data and our own data. It is merged at import time and is not shipped to the browser. Its allowed fields are described in the file; `entrance` records a provisional OpenStreetMap entrance and is how the 29 accepted entrances are stored.
- A room code prefix that should stay unlinked on purpose (for example `Y`, a retired Yale-NUS code spread across several buildings) goes in the overrides file's `unlinkedPrefixes`, with a reason. The report then shows the decision instead of a nearest-building hint.
- The curated abbreviation table is `frontend/scripts/buildings/aliases.ts`. Add an entry only where the dedupe report and the data support it.
- Proximity never links a room to a building; it only produces a warning.

## Limits

- Locations are API centroids (`locationKind: "centroid"`), except 29 buildings whose location is an accepted but unverified OpenStreetMap entrance (`locationKind: "provisional-entrance"`, node recorded in `sourceRefs`). The maintainer accepted those on 13/10/2026; they come from `entrance` entries in the overrides file. No entrance is verified yet, and a verified entrance will need its own `locationKind`.
- Building IDs are derived from names and `elementId` order. A future snapshot that adds a record with an existing name could renumber the `-1`/`-2` suffixes; an ID registry would be needed to prevent that.
- The API is beta and may change; the committed snapshot and boundary validation contain the damage.
- Explore groups buildings that share a name (for example Saga College) into one result, whose ID is the shared `groupKey`; each part keeps its own ID and marker. A group used as a trip endpoint resolves to the real part nearest the group centre, not to the centre itself, which may not be on any building.
- Room-to-building links come only from `roomCodePrefixes`. Against the committed data, 574 of 729 venues link and 155 do not (examples: `LAW_SR3`, `Pinnacle`, and the `Y-` rooms, whose prefix is unlinked on purpose). Unlinked venues behave as before. `SH-SR1` links to Sheares Hall, which is a one-room building in the data.
- Not verified: no location is an entrance, so the UI never says "entrance". Smoke checked on 15/10/2026 against the Vite dev server only (no backend or Valhalla): search, group details and Plan destination on a phone-width pane, and venue search on a wider pane. Route calculation to a building or group, dark and light themes side by side, keyboard-only use and real devices were not checked.
